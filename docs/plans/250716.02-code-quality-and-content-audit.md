## Part 1: Code Quality — Issues Found

### 1.1 🔴 CRITICAL: Competing CSS Design Systems (Duplicate Architecture)

`styles.css` (the original Elva theme) and `redesign.css` (the new Tokyo Night overlay) fight for control. Both are loaded in `base.njk` sequentially:

```
{% css %}{% include '../css/styles.css' %}{% endcss -%}
{% css %}{% include '../css/redesign.css' %}{% endcss -%}
```

`styles.css` uses the original Elva token system (`--foreground`, `--background`, `--link`, `--font-headings`, etc.) while `redesign.css` uses Tokyo Night tokens (`--text-primary`, `--bg-void`, `--accent`, `--font-sans`). The `variables.css` file provides backward-compat aliases (e.g., `--foreground: var(--text-primary)`), which creates a fragile chain of indirection.

**Impact:** Every new CSS rule must fight specificity wars. Debugging is unpredictable — a change in one file silently breaks another. New design changes are exponentially harder to implement.

**Fix:** Consolidate into a single source of truth. Options:
- **A)** Merge all surviving rules from `styles.css` into `redesign.css`, then delete `styles.css`
- **B)** Refactor `redesign.css` rules back into `styles.css` and drop `redesign.css`

Recommendation: Option A — `styles.css` carries legacy patterns (Nord palette, blog-centric layouts) while `redesign.css` represents the intended design direction.

### 1.2 🔴 CRITICAL: Unresolved CSS Variables (Nord Palette Ghosts)

These variables are referenced throughout the codebase but **never defined** in `variables.css`:

| Variable | Used In | Locations |
|---|---|---|
| `--nord0` | `styles.css:170,192`, `syntax.css:27` | `selection` bg, `mark` color, code selection |
| `--nord5` | `styles.css:253` | Notice link color |
| `--nord9` | `styles.css:234-235` | Notice background + box-shadow |
| `--nord11` | `styles.css:248-249`, `defer.css:112` | Notice error bg + lazy-load skeleton |
| `--nord13` | `styles.css:169-170,191,242-243`, `defer.css:114` | `mark` bg, figure selection, notice warning |
| `--nord10`, `--nord12`, `--nord14` | `defer.css:111,113,115` | Lazy-load conic-gradient skeleton |

**Impact:** All these rules resolve to `unset`/`initial` at runtime, breaking visual states (notices, code syntax highlighting, lazy-load skeletons, selection colors).

**Fix:** Either (a) map them to Tokyo Night equivalents in `variables.css`, or (b) rewrite the consuming rules to use Tokyo Night tokens directly.

### 1.3 🟡 MEDIUM: Filename Typo — `switch-il8n.css`

File: `themes/default/css/components/switch-il8n.css`

"il8n" is a typo — should be "i18n" (internationalization = i + 18 letters + n). The include in `switch-i18n.njk` references the typo'd filename, so it works, but it's a landmine for future developers.

**Fix:** Rename to `switch-i18n.css` and update the `{% include %}` in `switch-i18n.njk`.

### 1.4 🟡 MEDIUM: Orphaned Components — Dark Mode & Language Switches

Both toggle components exist in the codebase but are **never rendered**:

- `switch-darkmode.njk` + `switch-darkmode.css` — dark/light toggle, depends on Alpine.js `$store.elva.theme`
- `switch-i18n.njk` + `switch-il8n.css` — language switcher

**Evidence:** `header.njk` only includes `navigation.njk`. Neither switch is included from any layout. The CSS for `switch-darkmode` is still loaded (via `{% css 'defer' %}` in the component file), which means it ships to every page as dead bytes.

The Alpine store is initialized in `scripts.js` and `base.njk` wires `x-data` + `:data-theme`, but without the toggle UI, users can't switch themes. The site is effectively dark-mode-only.

**Fix:** Either (a) wire the dark-mode toggle into `header.njk`/`navigation.njk` to give users theme control, or (b) remove the dead components and Alpine theme store entirely, hardcoding dark mode. For the language switch: either wire it into the nav or remove it.

### 1.5 🟡 MEDIUM: Duplicate `::selection` Block

In `redesign.css`, the `::selection` rule is defined twice:

```css
/* Line ~5 */
::selection {
    background: var(--accent);
    color: var(--bg-void);
}

/* Line ~17 — identical */
::selection {
    background: var(--accent);
    color: var(--bg-void);
}
```

**Fix:** Remove the duplicate.

### 1.6 🟡 MEDIUM: Aurora Canvas — Two Divergent Implementations

Two canvas scripts exist with slightly different parameters:

| Parameter | `base.njk` (active) | `redesign-plan.md` spec |
|---|---|---|
| Blob count | 3 | 3 |
| Radius sizes | 260, 280, 230 | 400, 420, 350 |
| Time speed | 0.0006 | 0.001 |
| Mouse ease | 0.04 | 0.06 |
| Opacity values | 0.16, 0.13, 0.12 | 0.35, 0.30, 0.28 |
| Drift amplitude | 4% | 7% |

The `base.njk` version (which actually runs) has smaller, dimmer, slower blobs — more subtle than what the spec calls for. Neither is "wrong," but the spec promises one thing and the code delivers another.

**Fix:** Align the `base.njk` canvas parameters with the design spec, or update the spec to match reality.

### 1.7 🟢 LOW: No `font-display: swap` on Google Fonts

The Google Fonts URL in `base.njk`:

```
https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&family=JetBrains+Mono:wght@400;500&display=swap
```

Actually includes `&display=swap` — verified. **No issue here** on re-check.

But loading 6 font weights (Inter 400/500/600/700 + JetBrains Mono 400/500) is ~120KB+ of font data before the page renders text. Consider subsetting or using `font-display: optional` for the mono font.

### 1.8 🟢 LOW: `themeColorLight` Is a Dark Color

In `settings.json`:
```json
"themeColorLight": "#0d1117"
```

This is the browser chrome color for light mode users — but it's nearly black. Should be a light color or removed since the site doesn't support light mode.

### 1.9 🟢 LOW: `eleventy.globalData` Used Before Async Resolution

In `.eleventy.js` line ~75:
```js
const cssTemplate = fs.readFileSync(path.resolve(`themes/${eleventyConfig.globalData.settings.theme}/_layouts/`, 'css-opengraph.njk'), 'utf-8');
```

This accesses `eleventyConfig.globalData.settings.theme` which was set by `addGlobalData` a few lines above — it works but relies on synchronous data resolution. If settings ever become async, this breaks silently.

**Fix:** Hoist the theme name to a local const after `addGlobalData`.

## Part 2: Content — Issues Found

### 2.1 🔴 CRITICAL: Starter/Demo Content Still Published

The following posts are Elva starter-theme demo content, not real writing:

| File | Content |
|---|---|
| `getting-started.md` | "How to install Elva" instructions |
| `frontmatter.md` | Front matter documentation reference |
| `adding-additional-languages.md` | Draft with no body |
| `markdown-test.md` | Markdown syntax test page |
| `image-embed-example.md` | Embed example |
| `video-embed-example.md` | Embed example |
| `other-embed-examples.md` | Embed example |
| `imports.md` | Demo import page |

**Impact:** These appear in the post list on the home page and `/writing/`. They dilute the professional portfolio with framework documentation that belongs in the Elva README, not on a personal site.

**Fix:** Either delete them or set `eleventyExcludeFromCollections: true` + `draft: true`.

### 2.2 🟡 MEDIUM: Placeholder Tags Throughout Content

All posts use generic placeholder tags:

```yaml
tags:
  - tag1
  - tag2
  - tag3
  - tag4
  - tag5
  - unique
```

The taxonomy database confirms this: `["tag1","tag2","tag3","tag4","tag5","unique"]`.

**Impact:** Tag pages exist at `/en/tag/tag1/` etc., showing nonsense groupings. This looks unprofessional.

**Fix:** Replace with real semantic tags. Suggested taxonomy:
- `guide`, `tutorial`, `talk`, `slide-deck`, `game-dev`, `ai`, `web`, `vr`, `retrospective`

### 2.3 🟡 MEDIUM: About Page Duplicates Home Page Intro

**Home page** (`home.njk`):
> "Hey, I'm Aitor. I write code, make games, and teach sometimes. I live in the Canary Islands with two cats and a coffee habit. Nice to meet you."

**About page** (`about.md`):
> "Hey, I'm Aitor. I write code, make games, and teach occasionally. I live in the Canary Islands with my partner, our two cats (Marvel and Haru), and a steady supply of single-origin filter coffee."

The About page has slightly MORE detail (partner, cat names, single-origin coffee). The home page is a shorter version of the same intro.

**Impact:** Visitors who click "About" get deja vu. The home page should be a TL;DR; the About page should go deeper with different content.

**Fix:** Rewrite the home page intro as a one-line professional tagline + what the visitor can find on the site. Reserve the personal story for the About page. Or vice versa — make the home page personal/warm and the About page strictly professional.

### 2.4 🟡 MEDIUM: Teaching Page Is Underdeveloped

`teaching.md` is 19 lines of markdown — two bullet lists and a footer line. The 8 slide deck links have zero context: no descriptions, no dates, no audience info.

Compare this to what the redesign spec envisions: detailed course descriptions, metadata, slide pill badges with hover states. None of that exists in the content.

**Fix:** Add a one-line description for each slide deck (what topic, when presented, to which audience). Structure as:
```markdown
- [juiciness](url) — Game feel and juice techniques (2016, ULPGC undergrad lecture)
```

### 2.5 🟡 MEDIUM: Incomplete Swedish (sv) Translations

| | English (en) | Swedish (sv) |
|---|---|---|
| Posts | 19 | 9 |
| Pages | 4 (index, about, teaching, writing) | 2 (index, 404) |

Missing Swedish pages: `about.md`, `teaching.md`, `writing.md`. Missing Swedish posts: 10 posts have no `sv/` equivalent. The `adding-additional-languages.md` post exists in both languages but has zero body content — it's a draft shell.

**Impact:** Swedish visitors see English content for most pages. The i18n switch (if wired) would lead to 404s.

**Fix:** Either (a) translate the missing content, or (b) remove the Swedish locale entirely and redirect `/sv/` to `/en/` until translations are ready.

### 2.6 🟢 LOW: No "Now" Page Despite Spec Emphasis

The `terminal-design.md` and `leanrada-analysis.md` docs both heavily reference a "Now" section (current activities, reading, playing, working on). The `redesign-plan.md` explicitly says to create one inside a Bento grid cell. But no `now.md` page exists and the home page Bento grid doesn't include this data.

**Fix:** Either create a `/now/` page or embed the "now" data in the Bento grid as specified.

### 2.7 🟢 LOW: Navigation Doesn't Reflect Available Content

Current nav: Home · Notes · About

Available but unlinked: Teaching (`/teaching/`), slide decks (external), RSS feed, Mastodon/Bluesky/GitHub (only in footer).

The redesign spec calls for nav to include Teaching. The teaching page exists but users can only find it via direct URL.

**Fix:** Add Teaching to `navigation.js`.

### 2.8 🟢 LOW: CV/Profile Files in `docs/` Mix Concerns

`docs/` contains: `Profile.pdf`, `cv.png`, `cv-bn.png`, `cats.jpg` — these are personal assets, not documentation. They're mixed with analysis markdown files.

**Fix:** Move personal assets to `content/assets/img/` (where `cats.jpg` and `cv.png` already exist) and keep `docs/` for documentation only.
