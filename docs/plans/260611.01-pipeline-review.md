# Pipeline & code review

Reviewed 2026-06-11. Claims verified against a real `npm run build:prod` run (53 pages,
~4.5s) and inspection of `dist/`. Effort ratings: **S** (< 30 min), **M** (half-day), **L** (multi-day).

## Verdict in one paragraph

The 11ty pipeline itself (bundles, lightningcss, terser, html-minifier, eleventy-img) is solid
and well-organized. The two real problems are: **UnoCSS is wired in correctly but effectively
unused** — it ships only a CSS reset plus accidental noise while all real styling lives in
`redesign.css` — and **the publish path ships ~13 MB of raw source images** into a 15 MB
`dist/`. Everything else is hygiene-level.

---

## 1. UnoCSS integration — integrated, but dead weight 🔴

**Evidence**

- Generated `themes/default/css/unocss.css` is 410 lines: lines 1–404 are the wind4
  preflight/reset + theme variables; the only "utilities" emitted are
  `.m2 .my .me .flex .inline .transition` (line 405+) — **false positives** from the extractor
  matching prose words ("my", "me", "flex"…) in markdown content, not intentional usage.
- The shortcuts defined in [uno.config.js:43-47](../../uno.config.js) (`tag-pill`,
  `tag-pill-muted`, `card-surface`) appear in **zero** templates. Grep of all `class="…"`
  attributes across layouts/includes/content finds 107 distinct classes, none of them
  UnoCSS utilities — everything is styled by `redesign.css` (1,552 lines) + `variables.css`.
- The uno theme palette ([uno.config.js:8-19](../../uno.config.js)) duplicates the
  `variables.css` design tokens as hardcoded hex — a second source of truth that already only
  matches the *light* theme and will drift.
- Dev gap: `npm run dev` runs `unocss` once, then `eleventy --watch`
  ([package.json:12](../../package.json)) — new utility classes would never appear without a
  manual re-run. (Moot while nothing uses utilities, but it means the integration was never
  exercised.)
- The generated file is **committed to git and drifts on every build** (`git status` shows it
  modified right after a build).

**Recommendation — pick one, don't stay in the middle:**

- **Option A (recommended, S): remove UnoCSS.** Replace the inline include in
  [base.njk:41](../../themes/default/css/unocss.css) with a small static `reset.css`
  (~60 lines covers what the site actually relies on from the preflight). Delete
  `uno.config.js`, the three uno deps, and the `unocss &&` prefix from every script.
  Simpler build, one styling system, ~8 KB less CSS per page.
- **Option B (M): commit to UnoCSS.** Use the shortcuts/utilities in templates for the
  repeated patterns in `redesign.css` (tags, cards, metrics), source colors from
  `var(--…)` instead of hex, run `unocss --watch` in parallel during dev
  (`npm-run-all --parallel`), and gitignore the generated file. Only worth it if you expect
  heavy template iteration; the current handcrafted-CSS approach is serving the design fine.

## 2. Performance

### 2.1 Raw source images are published 🔴 (S to fix)

[.eleventy.js:169](../../.eleventy.js) `addPassthroughCopy('./content/assets/img' → '/assets/img')`
copies **every original** next to the optimized variants. In `dist/`:
`cliptarget.png` 2.4 MB, `en.jpg`/`sv.jpg` 1.7 MB each, `avatar.jpg` 1.2 MB, `cv.png` 1.2 MB,
`cv-bn.png` 0.5 MB → `dist/assets/img` is 13 MB of a 15 MB site. The eleventy-img transform
rewrites page references to optimized AVIF/WebP, so these originals are mostly unreachable —
but they're still deployed, and anything referenced with `eleventy:ignore` (e.g. `cats.jpg`
on the home page) is served raw (157 KB).

Fixes, cheapest first: delete unused leftovers (`en.jpg`/`sv.jpg` are Elva demo images,
`cliptarget.png` looks like a scratch asset); downscale/compress the rest at source; make the
passthrough selective (icons + favicon only) and let eleventy-img own the rest.

### 2.2 35 KB of CSS inlined into every page 🟡 (S–M)

[base.njk:41-46](../../themes/default/_layouts/base.njk) inlines unocss + variables +
redesign into a `<style>` tag: **35.4 KB minified per page**, repeated across all 53 pages,
uncacheable. Only tiny `defer.css` (2.5 KB) is an external file. Inverted priorities.

Fix: keep genuinely critical CSS inline (variables + above-the-fold layout, a few KB) and move
`redesign.css` to the external cached bundle (the `'defer'` bundle mechanism already exists,
or add a non-deferred external bundle). One-line change per file in base.njk.

### 2.3 Fonts: double family, many weights 🟡 (S)

[base.njk:57](../../themes/default/_layouts/base.njk) loads **Geist 400–700 + Inter 400–700 +
JetBrains Mono 400–500** from Google Fonts. The font stacks (`variables.css`, `uno.config.js`)
list Geist before Inter, so Inter is almost certainly never rendered — 4 wasted weight files.
Trim to the weights actually used (likely Geist 400/600, Mono 400), or better: self-host via
the existing `themes/default/fonts` passthrough ([.eleventy.js:170](../../.eleventy.js)) and
preload the primary woff2 — removes a third-party render dependency entirely.

### 2.4 Weather widget 🟢 (S, optional)

[home.njk:277-302](../../themes/default/_layouts/home.njk) fetches Open-Meteo client-side on
every home view, uncached, hardcoded to Las Palmas. It fails gracefully (hides itself). Fine
for a personal site; if you want it cleaner: cache in `sessionStorage` with a 30-min TTL
(3 lines), or fetch at build time with `@11ty/eleventy-fetch` (already a dependency) and
accept build-time staleness.

### 2.5 JS loading 🟢 (no action needed)

Alpine + intersect + scripts.js are concatenated into one deferred, versioned, terser-minified
bundle ([base.njk:126-129](../../themes/default/_layouts/base.njk)) — good pattern. Inline
home-page scripts get minified by html-minifier's `minifyJS` in prod. The only note:
Alpine powers a theme toggle, an expanding timeline, and a random quote — if you ever feel
like trimming, all three are doable in ~50 lines of vanilla JS, saving ~45 KB. Not urgent.

## Summary — what to fix first

1. **Decide UnoCSS: remove (recommended) or commit to it** — currently pure overhead (§1).
2. **Stop shipping raw images**; prune the 7 MB of leftovers (§2.1).
3. **`"private": true` + drop publish scripts + single lockfile** (§3) — five minutes, removes real footguns.
4. **Externalize redesign.css** for cacheability (§2.2).
5. **Trim/self-host fonts** (§2.3).
