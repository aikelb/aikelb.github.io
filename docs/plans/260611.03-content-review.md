## 2. Slide entries: embed + button + description

**Feasibility confirmed:** `slides.aitorlozano.com` serves reveal.js decks over HTTPS with
**no `X-Frame-Options` and no CSP `frame-ancestors`** → iframes work.
⚠️ One trap: URLs without a trailing slash 301-redirect to **plain `http://`**
(EasyEngine/nginx config), which browsers block inside an https page as mixed content.
The embed must use the exact canonical form, e.g.
`https://slides.aitorlozano.com/juiciness/` — verify each of the 9 final URLs once
(`slides-multiplayer` uses the odd `/multiplayer/slides` path and `slides-procedural` uses
`/exel-ii/1`; both need checking embedded).

**Proposed implementation** (follow-up pass):

1. Front matter: add `slides: <canonical-url>` to the 9 entries (keep the `slides` tag).
2. In [post.njk](../../themes/default/_layouts/post.njk): when `slides` is set, render —
   - a 16:9 `aspect-ratio` container with `<iframe src="{{ slides }}" loading="lazy"
     allowfullscreen title="{{ title }} slides">`,
   - a prominent "Open slides ↗" button (always shown — fullscreen reveal.js with keyboard
     nav is a much better experience than an embedded frame, and it doubles as the fallback),
   - and suppress the reading-time line for slide entries ("Less than 1 minute to read" is
     meaningless there — see [260611.02](260611.02-design-ux-review.md) §4).
3. Writing index: badge slide entries (🎞) so the two content types are distinguishable.
